{{ if eq .Values.rbac.impersonation.scope "namespaced" -}}
Impersonation is confined to: {{ join ", " .Values.rbac.impersonation.namespaces }}
A Weave in any other namespace will report a permission error, which is what
confining it means.
{{- end }}

A namespace user needs nothing from you to author one, but the ServiceAccount
their Weave names does need permission to read what its program reads and to
write its outputs. Weft tells them exactly what is missing, in commands they can paste:

  kubectl describe weave <name>

To try it:

  kubectl create serviceaccount composer
  kubectl create rolebinding composer-edit --clusterrole=edit --serviceaccount=$(kubectl config view --minify -o jsonpath='{..namespace}'):composer
  kubectl apply -f https://raw.githubusercontent.com/alethic/weft/main/examples/app.yaml

BEFORE YOU UNINSTALL: if any Weave reads a resource with hold=True, Weft
has placed finalizers on objects it does not own. Release them first, or those
objects cannot be deleted and neither can their namespaces:

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "weft.fullname" . }} -- /weft reap --dry-run
  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "weft.fullname" . }} -- /weft reap
